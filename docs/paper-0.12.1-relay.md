# 《封建社会》0.12.1 · 一张赈单过河

西岸庄有余粮，东岸庄缺粮，中间隔着一道河。供粮庄主现在可以一次委托从厅仓到厅仓的整段行程。脚夫把粮送到西岸站桶，船工从该桶装船，在东岸卸货，另一队脚夫从东岸站桶接手。地方持印人仍须到目的庄点收，封装粮在签收前不计入居民口粮。[下载插件](../examples/imperial-atlas/feudal-survey-0.12.1.jar)

## 游戏中如何办理

1. 缺粮庄所在领地的持印人在庄档申请赈粮。供粮庄业主或该处公产持印人到厅仓备货，留足本庄下季口粮，把整批带单号的面包放在第一格。
2. 在供粮庄赈单点「安排联运」，按行程填入一至八条已登记货线。第一段从供粮庄厅仓出发，最后一段抵达收粮庄厅仓。相邻路段必须共用同一世界、同一位置、同一登记编号的实体站桶。单趟运量受各段工班的装备限制。
3. 例如 `/freight relay 1 fieldport estuary dockmarket` 委托第 1 号赈单先走陆路，再乘船，最后走陆路。各段自动换装。修桥、疏通航道、疏空卸货位之后，工班会继续本段作业。路费、实体船与驮畜仍按各段原有规则办理。
4. 用赈单中的「联运进度」或 `/freight track 1` 查看最近一格的位置、阻塞原因及各段回执。原委托人可撤回尚未发车的路段；已出发的工班完成本段交仓。在行程页可恢复后续派车，工班会先核对原批封粮是否仍在站桶第一格。也可以亲自取货送达。
5. 最后一段交仓只完成运输。收粮庄的现任持印人亲临厅仓，点「验货签收」将全批转为普通面包。实际签收数量、季末居民食用数量和仓内余量可分别核对。

单服当前沿用一班承运队列，队伍实际回站后才派下一班。此版覆盖整批面包；一张单拆为多批、多支货队同时承运仍在后续路线内。

## 随机地图实测

Java 25、Paper 26.3 build 257、BlueMap 5.29。试验采用普通随机河港存档的独立副本，种子为 `-2271199516753095334`。沿用旧版路面、实体船、登记站桶和旧货单，在两端预置粮庄及首批物料。MillerGuest 是普通生存账号，测试中兼任供粮庄业主和收粮领地持印人。控制台用于设置阻塞、清障和移动观察视角。实拍船工使用项目原创人物资源包。BlueMap 上的七条货线、四处泊位、两座桥亭和两座商站均与账本吻合。[本版河港地图](screenshots/0.12.1/river-route.png)

| 现场 | 结果 |
|---|---|
| 检查路网 | 跳过中间航线时，两端没有共用站桶，委托遭拒。补上航线后，三份封粮按一张赈单发运。 |
| 陆路断一格 | 脚夫停在第一段第 3 格，面板指出缺口坐标。补回路面后整批交到西岸站桶。 |
| 撤回再续运 | 第一段在途中撤回后续派车。西岸站桶收到整批封粮，脚夫走回起点后船仍未出发。原委托人点恢复，船工才从同一桶取粮。 |
| 河道封闭后重启 | 船停在航线第 14／28 格，两个中转桶均无这批货。正常停服重启后进度仍是第 14 格。清障后原船继续，末段脚夫在东岸取货。 |
| 终点第一格被占 | 末段工班等候卸货。目的庄提前点收遭拒，原占位物也保留。腾出第一格后，仓内出现三份带同一赈单号的封粮。 |
| 验货与重复操作 | 持印人签收后得到三份普通面包，再次签收不能增发。三段货单保存的货物数据完全相同。 |
