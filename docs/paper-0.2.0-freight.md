## 断桥与交割恢复

测试路面为三格宽的橡木板，起点站桶在 `(8,100,8)`，终点站桶在 `(26,100,8)`，第一格货物为 17 份小麦。先在默认设置下开单并验证空服暂停。后续无玩家的故障注入使用 `freight.pause-when-empty: false`。道路施工用的原版强制加载在运输前解除。

| 操作 | 实服观察 |
| --- | --- |
| 连续两次提交同一单号 | 仅一条货单。空服期间起点桶仍有原来的 17 份小麦 |
| 暂时用 SQLite 测试触发器拒绝 LOADING → TRAVEL，观察站桶后强制终止 JVM | 起点桶第一格已空，桶上留下该单的装货回执。移除测试触发器并重启，货车从起点继续 |
| 行至第 2 格时拆除 `(16,100,9)` 的桥边木板 | 货车停在第 7 格，中心坐标 X=15。可查询阻塞坐标，路上有货车展示实体，终点桶为空。提前签收遭拒 |
| 将断桥保存到地图后，在第 7 格强退重启 | 同一货单保持第 7 格，仍等待同一块桥面 |
| 修桥，再在 `(19,103,8)` 设置遮挡 | 货车恢复后停在第 10 格，报告第三格净空不足。移除遮挡后到达第 18 格，等待现场签收 |
| 终点桶第一格预放石头，再签收 | 卸货等待，原来的石头保留 |
| 腾空槽位，拒绝 UNLOADING → DELIVERED，再次强制终止 JVM | 此时终点桶有 17 份小麦和卸货回执。移除测试触发器后重启，补齐原单交付状态 |
| 重试签收、重试同一发货请求 | 返回原回执，最终一张货单。源桶第一格为空，终点第一格仍恰有 17 份小麦 |

使用两个回环地址上的 Minecraft 26.3 游戏协议连接，以普通白名单玩家身份登录隔离测试服。两端使用默认的空服暂停规则。发货人手持普通书右键站桶收到了可填写的货单。远处开单及非收货人签收均被拒绝。发货人给另一玩家发出 13 份白色羊毛后离开服务器，收货人收到到站通知，持书检查站桶并签收成功。测试通过游戏协议验证命令、站桶交互、消息与库存，真人客户端渲染效果仍待体验。
