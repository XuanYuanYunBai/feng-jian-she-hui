# La Société féodale · Minecraft 多人封建社会

面向 Paper 26.3 stable build 257、Java 25 的服务器插件。当前版本 0.1.1 提供开服前主世界勘测，支持从同一种子逐圈扩图及中断续跑。[实服测试记录](docs/paper-0.1.1-test.md)

## 已实现的勘测流程

管理员在新主世界开放建设前运行 `/survey start`。插件固定世界 UUID、种子、生成器标识、原始出生坐标与规则版本。首轮以出生区块为中心，扫描 256 × 256 个区块。每完成一整轮，若铁、铜、金任一项未达配置门槛，每侧扩 32 个区块，只扫描新增部分。首次整轮达标即停止。默认最大半径为 256 区块，可按服务器磁盘与预生成预算调整。

每批最多预生成 32 个区块，Paper 完成主世界同步存盘后，服务器主线程逐个捕获区块快照，单一后台工作线程遍历全部高度并写入 SQLite。任一时刻最多处理一个区块。统计包含普通矿石与深层矿石，单位是地图上实有的矿石方块。勘测本身会生成尚未探索的区块，建议先在新测试存档运行。

| 管理员命令 | 行为 |
| --- | --- |
| `/survey start` | 首次建立记录并开始；已有记录时显示当前状态 |
| `/survey status` | 查看中心、半径、圈内进度，以及每项矿量的实测值和门槛 |
| `/survey pause` | 暂停扫描，已提交的区块保留 |
| `/survey resume` | 从检查点继续。触及预算后，可调高配置中的最大半径，重启后继续扩圈 |

命令需要 `feudal.survey.admin`，默认仅 OP 与控制台可用。区块测量与游标移动在同一事务提交，数据库保存在 `plugins/FeudalSurvey/survey.sqlite`。运行中的勘测会在重启后继续，已暂停的勘测保持暂停。首次勘测后的出生点移动不会重定中心。修改矿量门槛、初始半径或步长会触发存档规则检查。

## 构建与安装

使用 JDK 25 与 Maven 3.9，在项目根目录运行 `mvn clean verify`。将生成的 `target/feudal-survey-0.1.1.jar` 放入 Paper 26.3 build 257 的 `plugins/`，重启服务器。数据库驱动使用该构建自带的 SQLite JDBC。首次启动会生成 `plugins/FeudalSurvey/config.yml`。

小规模复验可以在全新测试存档首次执行命令前，把初始半径和步长设为 1，最大半径设为 2，并重启服务器。将一项门槛设为 1000000000，可观察首轮四个区块、次轮十二个区块与预算停机。中途暂停并重启，检查状态及坐标保留。默认配置适用于较大规模的预生成实验。

0.1.1 首次读取 0.1.0 的勘测存档时，把原始记录保留在同一数据库的 `survey_v010` 和 `chunks_v010` 表，沿原种子、出生点和门槛重新测量。原来运行中的任务自动复核，原来暂停或已结束的任务等待 `/survey resume`。请在开放建设前完成复核，测量结果反映复核时的地形。

## 验证范围

自动化测试覆盖正负坐标及外圈覆盖、普通与深层矿石识别、首个达标整圈停止、预算续扩、暂停重开、旧回调重试、事务回滚与世界或规则不匹配。后端测试使用真实 SQLite 文件。

本里程碑只验证三项原版矿石的扫描与续跑。正式版的独立可达矿源、地质生成、粮食与种畜供给、盐场、航道试航和三个起始据点仍待实现。当前门槛用于验证扫描流程。三项达标后只生成勘测结果，开服边界仍由管理员控制。

### 0.1.0 验证记录

2026-11-21 在 Linux、Corretto 25.0.5.1、Maven 3.9.11 上连续两次干净构建，8 项测试全部通过，两次 JAR 的 SHA-256 均为 `e000bb71a07a9dc1bcfdc51cfcb4bc8e7a3a7285c1656e2a9150cb0a8628a5cd`。Paper 26.3 build 257 在 `--initSettings` 启动检查中识别到 `FeudalSurvey (0.1.0)`。后续实服强退测试发现世界文件与勘测账本之间的存盘窗口，修复及复验见 [0.1.1 实服测试记录](docs/paper-0.1.1-test.md)。
