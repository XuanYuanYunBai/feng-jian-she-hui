# 封建社会 · 0.4.1 试玩

0.4.1 的历史测试场景称为“河湾帝国”。现行版本由帝国组织登记成员与各自的辖区。测试使用随机种子的普通主世界。在全新的 Paper 实例首次启动前，复制同目录的 [server.properties](server.properties) 到服务端根目录。留空的 `level-seed` 会在创建世界时抽取种子。重启已生成的世界会沿用原种子。如需另抽种子，另建测试目录。

将同目录的 `feudal-survey-0.4.1.jar` 放入 Paper 26.3 build 257 的 `plugins/`，使用 Java 25 启动。升级旧版时替换旧插件 JAR，保留原有插件数据目录。启动后请一位玩家上线，管理员执行 `/realm init 玩家名`。这只会建国一次。君主和封臣日常操作均可由普通权限玩家执行。

## 人物与资源包

首次登录时接受“封建社会”的服务器资源包。仓务脚夫穿苔绿色头巾与围裙，货站脚夫戴蓝布帽；驻地的世俗执事和教士也各有一套服装。右键税仓脚夫可打开仓务装备页，右键 NPC 封臣的驻地代表可打开领地档案。旧版登记脚夫在所在区块加载后原地转换，原有装备与货物随职务保留。

默认从 GitHub 的固定版本下载约几 KB 的[原版资源包](feudal-people-v1.zip)。若玩家所在网络难以连接 GitHub，可将同一个 ZIP 放在玩家能访问的 HTTP(S) 地址，在插件配置中设置 `npc.skin-pack-url` 并重启。已有整合资源包的服务器也可以合并其中的 `assets/feudal/` 并把该配置设为空字符串。

## 看地图，找到自己的税源

输入 `/realm` 打开中文纹章院对话框。点击领名可查阅法定任命、实际持印人、驻地、领界和财权。点击“疆域图”取得全图，低头看手中地图，右键可返回图册。`/realm local` 展开身边 25×25 区块的地图。`/realm here` 查询脚下土地，`/realm depots` 给出已加载仓房的账台坐标；远处仓房标注所在区块。找到有中文牌匾的木石仓房，右键牌匾或屋内账台即可查账。在旧存档中，税仓区块加载时会尝试建造，完成后替换旧标记。已占用的场地保留原有方块。若无法选址，持印人可在该区块留出七格见方的空地（西磨坊正面另留一格给风帆），再用 `/realm build` 补建。

建国以主世界出生区块为原点。王城、东境伯领和主教驻地各有 16×16 个区块，后两处分别在王城以东 1024 格和 2048 格。未登记土地也会在图册查询中明确显示。辖区可以沿实际区块边界划成不规则形状。

## 改建和搬仓

税仓初次选址成功时搭建木石仓房，屋内配置账台与产地桶。初始领地驻地另配公库桶。持印人可以拆墙、扩建装卸场、改屋顶，也可以在原登记区块另建整座仓房。将准星对准五格内的新设施，在税仓账簿点击“改建登记”选择用途。

| 要登记的设施 | 对准方块后输入 |
| --- | --- |
| 新账台 | `/realm desk 税仓ID` |
| 产地仓箱，存放本期产出的封缄税箱 | `/realm stock 税仓ID` |
| 领地驻地公库，存放实际收入的小麦 | `/realm vault 头衔ID` |

用讲台做账台，箱子或木桶做仓箱。两个角色各用一个独立容器，双箱只登记所指的半边。改登记后，仓务从新址办理。旧箱里的物品留在原位，可由玩家分批搬走。普通玩家可以按原版方式开箱、取放或把小麦合成干草捆堆在仓内。公库盘点统计登记箱内的散装小麦。新封出的头衔也可在自己的驻地区块登记公库。

## 脚夫与驮队

每座有装卸空间的税仓分配一名常驻脚夫。脚夫从产地取得实物包裹，自行寻路到公库，卸下小麦后步行回仓。玩家在仓边准备材料，打开“脚夫与装备”，也可以用 `/realm equip 税仓ID 装备代号` 当场交付。税仓装备由当地持印人置办。

| 装备代号 | 当场交付 | 游戏效果 |
| --- | --- | --- |
| 初始 | 随税仓配备脚夫 | 徒步，每趟 8 份 |
| `speed` 步鞋 | 1 双皮革靴 | 提高行走速度，载量保持当前等级 |
| `pack` 背架 | 4 张皮革、4 根木棍 | 徒步每趟 16 份 |
| `mule` 驮具 | 1 个箱子、1 根拴绳、1 副鞍，并已备背架 | 带来自己驯服的成年骡子，准星瞄准后编入原队，每趟 64 份 |

驮骡可按原版玩法用马和驴繁育并驯服。交装备时脚夫须在仓边，骡子须空载。升级按仓、站分别保存。货队在已加载的路段行走，门口宜留装卸场。堵路或满仓会耽误交割，持印人可到脚夫身边潜行右键接走税箱。

## 亲征、交割和赠纳

| 地点 | 默认本期应收 | 可委托脚夫 | 发运前可亲提 |
| --- | ---: | ---: | ---: |
| 王城市集 `town` | 16 | 16 | 16 |
| 王城以西 80 格的西磨坊 `mill` | 16 | 8 | 16 |
| 王城以东 112 格的东渡仓 `ford` | 16 | 0 | 16 |

前往东渡仓，在账簿选择“从本仓提运”或输入 `/realm collect ford`。把原箱随身运到王城，在公库箱六格内手持税箱，选择“交付手中税箱”或使用 `/realm deposit`。打开公库容器可以看见小麦。`/realm treasury crown` 盘点登记箱，驻地未加载时显示待盘点。散装小麦也可以直接放入公库箱。

每累计约 20 分钟有玩家在线的游戏时间进入下一税期，每仓产生 16 份试算小麦。旧期税箱可按 `/realm collect 仓ID 税期` 查提。每个税箱的编号只能交割一次。丢失后须找回原箱。持印人可在辖地用 `/realm depot 仓ID 仓名` 登记新税源，从下一期开始装箱。

玩家持印人在本领公库用 `/realm gift 本领ID 数量` 提出实物赠粮。君主到访 NPC 公库可用 `/realm visit 本领ID` 请求赠纳，每期答复一次。NPC 留下至少 12 份口粮，地方支持和官印争议影响答复。获准的粮食从当地箱进入来人的背包，由承运人送进上级公库。

旧版账本中的余额会在原领公库首次有空间时落为小麦。既有在途税箱可继续交割，同期已经结清的部分保留原记录。

## 授地与划界

坐标均为**绝对区块坐标**。矩形参数依次为西、北、东、南，含两端。在负方块坐标也按向下取整换算。授地仅能从自己的直辖地划出，须保留授予者驻地；已有独立收益封契的区块须保留原有权利。位于示例坐标原点以外的世界，请把所有示例坐标平移到实际王城。

| 命令示例 | 结果 |
| --- | --- |
| `/realm register crown 8 -8 23 7` | 君主把共边、无人持有的土地登记为直辖地，每次最多登记 256 区块 |
| `/realm preview crown 公爵 river 河东公国 玩家名 4 0 7 2` | 在自己的地图看选区；用相同参数将 `preview` 换为 `grant` 即颁发封契 |
| `/realm grant river 伯爵 fordcount 东渡伯领 玩家名 7 0 7 1` | 公爵将两个区块封给伯爵 |
| `/realm estate fordcount 庄园 farm 渡口庄园 玩家名 ford` | 授予东渡税源收益，管辖和效忠关系保留在伯领。种类还有修院、磨坊和地租 |
| `/realm grant crown 流官 gov 北部行署 玩家名 8 -8 22 7` | 任命流官治理 240 区块 |
| `/realm estimate gov 23 -8 23 7` | 地图显示追加后合计 256／256，核对后用 `extend` 替换 `estimate` 生效 |
| `/realm patent crown 修院 west 西岸修院 npc-Abbot -7 2 -6 2 维护驿道` | 皇帝另立直属特许并记录条件。可授伯爵、城市或修院 |

普通封契由皇帝或国王授公爵、公爵授伯爵。伯爵以下可授庄园等收益。流官的所有辖地跨职位合并计算，任何一次超额追加整笔回退。受封者可写在线玩家名，或用 `npc-名字` 指定署理家族。已入账的土地、官印与税物随世界重启恢复。

## 任期、家产和官印

1. 持印人用 `/realm heir 头衔ID 人名` 提名家族继任人。在本领境内，其他玩家可用 `/realm support 头衔ID` 联署，每个任期每人一次。每度过一税期增加一点任职资历，最多两点。
2. 积累至少两点联署或资历后，持印人可用 `/realm petition 头衔ID` 请袭。上级用 `/realm confirm 头衔ID` 明确准许。世袭家族也可用 `/realm relinquish 头衔ID` 交回该项特权。
3. 持印人用 `/realm vacate 头衔ID` 触发该职出缺。已登记的家产按各自文书交给继承人。普通官职由提名者暂管；有准袭文书的官职直接交接。公库始终挂在头衔下。
4. 上级用 `/realm appoint 头衔ID 人名` 颁发任命书。新任与持印人为同一人时立即结案，否则由实际持印人执行 `/realm yield 头衔ID` 或 `/realm resist 头衔ID`。NPC 持印人由直属上级请求执行，支持和资历不足两点时接受交印，达到两点时抗命。任何人都可以用 `/realm brief 头衔ID` 核对两人的身份，用 `/realm acts 头衔ID` 查阅文书。

## 帝内王国与独立和约

皇帝使用 `/realm offer 公爵领ID 王号 协议条件` 拟约，公爵用 `/realm ratify 公爵领ID` 接受，成为仍向帝国效忠的国王。日后只有帝内国王能以 `/realm offer 王国ID 独立 和约条件` 提议独立，皇帝签署后才解除上级关系。两次协议各自保留在文书记录中。王号和隶属关系即时生效，具体军事勤务以文字条款留档。

自动税距按税仓到本领驻地的东西、南北区块数之和计算。默认三步以内自动全收，第四至第六步依次为 75%、50%、25%，第七步归零。可在 `config.yml` 把 `realm.chunks-per-tax-step` 从 1 改为 2，重启后对新税期生效。每两区块算一步，余数进一；亲征额度仍按剩余应收计算。
